# Changelog

All notable changes to the Project Management API will be documented in this file.

This project follows the principles of **Keep a Changelog** and uses **Semantic Versioning (SemVer)** where applicable.

---

## Versioning

Version format:

```
MAJOR.MINOR.PATCH
```

Example:

```
1.2.0
```

### MAJOR

Breaking changes.

Example:

- Authentication system redesigned.

---

### MINOR

New features.

Example:

- Added task labels.

---

### PATCH

Bug fixes and minor improvements.

Example:

- Fixed login validation bug.

# Updating the Changelog

Update this file whenever:

- A new feature is added.
- An existing feature changes.
- A bug is fixed.
- Security improvements are made.
- A release is created.

Avoid documenting trivial formatting or comment-only changes unless they affect project documentation significantly.
