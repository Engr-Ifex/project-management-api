## 1. Project-detail privacy

**What was leaking.** `getWorkspaceProjects` (list) and `getProjectById` are
readable with `requireWorkspaceMember` alone, and both populated
`members.user` with `'name email avatar'` and `createdBy` with
`'name email avatar'`. So any workspace member could enumerate every project's
membership **and every member's email address** without being on any of those
projects.

**Fix — conditional response shaping** (the user explicitly sanctioned
"conditional response shaping or authorization-aware population"). Discovery is
preserved; member identities are not:
- unauthorized caller → `members` **removed**, `createdBy` reduced to an id.
- project member, or workspace owner/admin (Policy A) → response unchanged.

The elevation rule is read from `hasProjectOverride(workspaceRole)` via the
controller, the same helper `requireProjectPermission` uses, so shaping and
guard cannot disagree.

**Only two functions needed changing** — every other populate site
(updateProject, archiveProject, addProjectMember…) is behind
`ws:UPDATE_WORKSPACE`, so the caller is already elevated.

## 2. Upload content/signature validation

`src/utils/fileSignature.js` (new). Magic-byte detection for PNG, JPEG, GIF,
WEBP, PDF, ZIP (covers `.docx/.xlsx/.pptx`) and OLE2 (covers `.doc/.xls/.ppt`),
mapped to the allowed MIME types. **No dependency added** — the existing
allow-list needed no new package.

- **Attachments** use `multer.memoryStorage()`, so there is no temp file at all;
  the check runs inside `assertFileIsAllowed` before the storage provider and
  before any DB record.
- **Avatars** use `multer.diskStorage()`, so multer writes BEFORE anything can
  inspect it — the middleware reads the header back and **unlinks on rejection**.
  This closed a real hole: the avatar filter only checked the declared MIME type,
  so an HTML file sent as `image/png` was stored under its original extension in
  a **statically served** directory.

Text formats (`text/plain`, `text/csv`, `text/markdown`, `application/json`)
have no magic number. The check is only "is plausibly text" (no NUL, no control
chars beyond tab/newline/CR) and is **documented as weak** rather than dressed
up. A test enforces that every allowed MIME type has a content rule, so adding
one without deciding its content fails the suite.

## 3. Stale documentation

`ENVIRONMENT.md` was the worst: it documented `JWT_SECRET`, `JWT_EXPIRES_IN`,
`CLIENT_URL` and `RATE_LIMIT_MAX_REQUESTS` (none exist), omitted 8 of the 14
real variables, and its "example `.env.example`" listed `SMTP_*`,
`CLOUDINARY_*`, `REDIS_URL`, `SENTRY_DSN` — which are **not** in the real file,
so it described a file that does not exist. Rewritten against `env.js`.

`SECURITY.md` claimed password rules that do not exist — uppercase, lowercase,
digit and special-character requirements. The real policy is **minimum 8
characters, nothing else**. Also corrected the auth flow (the token travels in
an httpOnly cookie, not a client-held header).

`SETUP.md`, `ARCHITECTURE.md`, `CONTRIBUTING.md` — env names and example
constants swapped for real ones. Verified all 15 `npm run` scripts referenced in
docs actually exist.

Remaining mentions of the old names are intentional: `AUDIT.md` (historical),
`README.md` ("JWT_SECRET is not read by anything"), and `ENVIRONMENT.md`'s
"Not Implemented" section which lists them as things that do nothing.

## Gotchas worth remembering

- **`git checkout HEAD -- <file>` wipes the uncommitted remediation.** I used it
  on `memoryStore.js` and destroyed the previous turn's four fidelity fixes. The
  staged copy saved it: `git checkout -- <file>` restores from the **index**.
  When the work is staged, restore from the index, never from HEAD.
- **The test double cannot represent a populated nested array.**
  `makeDocument` → `Model.hydrate` casts `members` against the subdocument
  schema, so a populated `members[].user` comes back `undefined`. Implementing
  the populate made things WORSE than leaving the id. So the privacy tests assert
  the *decision* (`members` present/absent, `createdBy` populated or not) rather
  than member contents. Commented in the double so nobody re-attempts it.
- Both fixes were verified **discriminating**: disabling the shaping fails 4
  tests; disabling the content check fails 8.
