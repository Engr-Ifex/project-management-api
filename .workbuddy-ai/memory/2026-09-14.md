# 2026-09-14 — Phase 10 follow-up: 3 issues corrected

Addressed the three outstanding issues from the Phase 10 Comments implementation.

## 1. Backfill migration (NEW)
`server/src/migrations/migrateTaskComments.js` — follows the `migrateProjectMemberRoles.js` pattern (dotenv + `mongoose.connect(process.env.MONGODB_URI)` + raw `Model.collection` access + try/catch/finally disconnect).
For each legacy comment:
- `author` ← legacy `user`, then `$unset` `user`
- `project` ← derived from the owning task (`Task.collection.findOne`)
- sets `isDeleted:false`, `editedAt/deletedAt/deletedBy:null` defaults
- **Critical**: reads filter on `isDeleted: false`, and a *missing* `isDeleted` does NOT match that filter — without this backfill legacy comments would silently vanish from the API.
- Skips (never deletes) comments with no author/user or a missing owning task; logs them.
Run with: `node src/migrations/migrateTaskComments.js`

## 2. Explicit moderation capability
- `PROJECT_PERMISSIONS.MODERATE_COMMENT = 'comment:moderate'` added.
- Granted to project **OWNER + ADMIN only** (not MEMBER, not VIEWER).
- `deleteTaskComment` now allows author OR moderator (project owner/admin via `comment:moderate`, or workspace owner/admin via the existing `UPDATE_WORKSPACE` override). Plain members/viewers still cannot.
- **Update stays author-only** — editing another user's words is not moderation; no role may override it.
- Moderated deletions are audited: activity metadata gains `authorId` + `moderated: true` when the deleter is not the author.
- Controller computes `isWorkspaceElevated` with the same `hasPermission(role, UPDATE_WORKSPACE)` helper `requireProjectPermission` uses.

## 3. Global CastError handling
`error.middleware.js` now maps Mongoose `CastError` → HTTP 400 with `message` + `errors:[{field}]`, instead of a bare 500. Existing `ApiError` (statusCode) and unknown-error (500) behavior preserved.

# 2026-09-14 (later) — Phase 11: LABELS

Built the Label module from scratch (no scaffolding existed). 5 new files, 6 modified.

## Relationship decision (Task ↔ Label)
References, not duplication: `Task.labels = [ObjectId ref 'Label']`. A label belongs to one project and is reusable across that project's tasks. `Label.project` is the ownership anchor.

## New files
- `src/models/Label.js` — project, name (1-50), color (HEX_COLOR_REGEX), timestamps. Unique compound index `{project,name}`; listing index `{project,createdAt}`.
- `src/validators/label.validator.js` — create/update/list/id/assign/remove schemas; ObjectId-regex params, hex color, "at least one field" refine on update.
- `src/services/label.service.js` — create/list/get/update/delete + assign/remove; ProjectActivity logging.
- `src/controllers/label.controller.js`
- `src/routes/label.routes.js` — 7 routes.

## Modified
- `src/models/Task.js` — added `labels` ref array + `{project,labels}` index.
- `src/constants/regex.js` — added `HEX_COLOR_REGEX`.
- `src/models/ProjectActivity.js` — enum += label_created/updated/deleted/assigned/removed.
- `src/services/task.service.js` — labels populated at all 11 task-returning sites (verified count matches createdBy/assignee).
- `src/routes/index.routes.js` — mounted labelRoutes under `/workspaces`.
- `src/middlewares/error.middleware.js` — added MongoDB 11000 → 409 mapping (backs the unique label index against races).

## Key design points
- **Cross-project isolation is at the query level**: `getProjectLabel(projectId, labelId)` always scopes by project, so another project's label is indistinguishable from a missing one → 404. This single guard covers read/update/delete/assign (reqs #8, #9).
- **Delete cleans up references**: `Task.updateMany({project, labels: id}, {$pull:{labels:id}})` runs before `label.deleteOne()` so no task keeps a dangling ref.
- Duplicate label name → **409** (matches `Email already exists` / `User is already a project member`). Already-assigned label → **400** (matches `Task is already assigned to this user`). Both precedents were followed deliberately.
- Permission grants already existed and were used as-is: create/update/delete = owner+admin only; assign = owner+admin+**member** (members can tag, not manage labels); viewer = none.
- Label name uniqueness is **case-sensitive** (`Bug` vs `bug` are distinct) — documented, not changed.

## Critical fix — Express 5 `req.query` is a getter
