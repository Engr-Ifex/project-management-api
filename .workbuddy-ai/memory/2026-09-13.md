### Key design decisions
- Authorization is middleware-based (`requireProjectPermission`), matching the tech stack. Object-level ownership is enforced in the service because middleware cannot express per-object rules.
- Update/delete are **author-only**. The role-permission table grants generic `comment:update`/`comment:delete` to owner/admin/member but defines no explicit "moderate other users' comments" capability, so requirement #8's default (no cross-user modification) was applied strictly.
- Deleted comments are filtered out of all reads; update/delete on a soft-deleted comment returns 404 so content is never exposed.
- Activity metadata stores only `taskId` + `commentId` (never comment content).
- Fixed a pre-existing bug: comment update was logging the generic `task_updated` action; now logs `task_comment_updated`.
