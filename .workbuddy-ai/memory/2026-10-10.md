### The one real defect found and fixed (2.16)
`AcceptInvitation.tsx` treated an **expired** invitation as generic "no longer valid".
The backend distinguishes them: a 410 means expired-and-marked (`Invitation has
expired`), a 404 means already accepted / bad token. Only the 410 is recoverable by
asking for a fresh invitation, so the two now read differently. Verified live: an
already-used token 404s, an expired one 410s (pinned by
`workspace.test.js` "rejects an expired invitation with 410").

### Test-harness defect found and fixed (the important one)
`npm test` was **373/375**, not 375/375. Two failures: `transactions` and
`database integrity (real MongoDB)`. Root cause was NOT a code regression —
`startInMemoryMongo()` used `MongoMemoryServer.create()`, which starts a **standalone**
mongod. `hello` reported `setName: (none)`, topology `Single`.

Consequence: `supportsTransactions()` returned **false**, so `runAtomically` silently
took its no-session path and every transaction assertion passed **for the wrong
reason**. The integrity test that asserts a replica set really reports transaction
support could therefore never pass — 2 of 9 subtests, failing correctly.

Fix in `tests/helpers/setup.js`: `MongoMemoryReplSet.create({ replSet: { count: 1,
storageEngine: 'wiredTiger', version } })`. Result: `setName: testset`, topology
`ReplicaSetWithPrimary`, `supportsTransactions: true`, **375/375, 0 fail**.

**Trap:** `MongoMemoryReplSet.getUri()` already appends `?replicaSet=<name>`. Appending
it again yields `testset?replicaSet=testset`, and the driver treats that as the literal
set name → 30s `ServerSelectionError` with a confusing `ReplicaSetNoPrimary`. Use
`getUri()` as-is.

**What this means:** earlier notes claiming "375/375" were measured under a harness that
could not have been exercising transactions. The in-process store still cannot — this
matters only under `TEST_DB=mongodb`.

### The two defects that mattered
1. **Every focus ring in the product was invisible.** The global rule was a bare
   `:focus-visible` (specificity 0,1,0) and lost to Tailwind's
   `.focus-visible\:outline-none:focus-visible` (0,2,0). `Input`, `PasswordInput`,
   `Select`, `Checkbox`, `Tabs` all pair a ring with `outline-none`, so the ring was
   stripped. **Trap: a bare `:focus-visible` rule in `@layer base`/plain CSS does NOT
   win against a utility class+state selector.** Fix: wrap the rule in `:where()`
   (zero specificity) so it sits below the utilities. Verified by real Tab keypress:
   before `outlineStyle:"none"`, after `2px rgb(52,133,121)`.
2. **Toast viewport overflowed the mobile viewport.** `fixed` + `w-full` + `right-0`
   + `p-4` = 434px in a 390px viewport → 44px of sideways scroll **on every page**,
   invisible until a toast fires. Fix: `inset-x-0 … w-auto max-w-full`.

**Trap: `element.focus()` is not a keyboard Tab.** Script-driven focus never satisfies
`:focus-visible`, so a harness that calls `.focus()` and then asserts a ring or a
keyboard-only reveal reports a **false failure against a correct page**. Must dispatch
real `Input.dispatchKeyEvent`. Both keyboard checks were false negatives before this.

**Trap: do not filter console 401s by matching the message text** — that also hides a
genuine 401 from an unrelated request. Tag them with the phase that produced them.
The two legitimate 401 windows are the wrong-password login and the anonymous session
probe (which happens on the *first* `/login` load and after sign-out).

**`sr-only` looks exactly like clipped content** — it is a 1×1px clipped box *by
design*; its `scrollHeight` always exceeds its `clientHeight`. A filter that infers
invisibility from *descendant* styles fails, because the clipped element **is** the
sr-only span and has no descendants. Exclude by the defining rule: clipped **and**
≤1px, or clipped **and** out of flow. (Cost me two wrong diagnoses.)

**`/design` is a public route with no `RequireAuth`**; `/login` uses `RequireAnonymous`
so an authenticated browser is redirected off it — a harness that navigates to
`/login` after a page sweep must sign out first. Login does **not** use `AppShell`,
so it has no skip link; that check must run on an authenticated page.
