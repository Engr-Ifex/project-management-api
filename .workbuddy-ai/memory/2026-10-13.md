## PROJEX — manual-testing bug fixes (7 issues)

Report: `BUGFIX-REPORT.md`. Product renamed to **PROJEX**. No commit made.

### Root causes (all reproduced, none guessed)

1. **New Task dialog clipped its footer.** `ModalContent` is `flex flex-col` +
   `max-h` + `overflow-hidden` and depends on `ModalBody`'s `flex-1 overflow-y-auto`.
   Every dialog wrapped its content in a **bare `<form>`** — not a flex container,
   so `ModalBody` stopped being a flex item and the form kept `min-height: auto`
   and refused to shrink → the form grew past `max-h` → `overflow-hidden` clipped
   the footer. **All 5 dialogs had it**; only New Task had enough fields to show.
   Fix: new `ModalForm` primitive (`flex min-h-0 flex-1 flex-col`) — the `min-h-0`
   is the load-bearing part.
2. **Due date: two coupled defects.** (a) `<input type="date">` gives `yyyy-mm-dd`
   and the create handler sent it verbatim, but the API validates
   `z.string().datetime()` → 400. Create-without-date worked because the key was
   never sent. Same bug in `Projects.tsx` create (`deadline`). (b) These are
   **calendar dates** stored as `T00:00:00.000Z` but rendered with
   `toLocaleDateString()` → on UTC−7 a due date of the 19th showed **11/18**.
   Fix: `fromDateInputValue` / `formatCalendarDate` in `lib/utils/format.ts`.
   `createdAt`/`updatedAt`/`joinedAt` are instants — keep local rendering.
3. **Session: no defect.** Verified by decoding a live token: `Max-Age=900` and
   `exp − iat = 900`; client broadcasts on **401 only**; 403 is used for every
   permission failure; probe race is guarded by a `generation` counter. The
   15-min absolute lifetime is the documented policy → preserved. Hardened the
   real weakness: `COOKIE_MAX_AGE` was independent of `JWT_ACCESS_EXPIRES_IN`
   (different units, `15m` vs `900000`), so one could silently expire before the
   other. Now derived when unset + warned at boot. Also: the probe's
   `AbortController` signal never reached `fetch` — now passed.
4. **Status/priority/assignee 400'd.** `updateTaskSchema` accepts only
   title/description/startDate/dueDate/estimatedTime; the three fields have their
   **own** routes. Zod strips unknown keys → `{}` → the "at least one field"
   refinement fails. `TaskProperties` used the generic PATCH; the client already
   had `setStatus`/`setPriority`/`setAssignee`. TS missed it because the body was
   passed as a **variable** (structural typing allows extra props on a non-literal).
5. **Header/value misalignment.** `TH numeric` right-aligns, `TD numeric`
   right-aligns — the date columns had it on the cell but not the header. Four
   columns: task Due, project Deadline + Updated, members Joined.
6. **Avatar uploaded fine and could never display.** The API stores the relative
   `/uploads/avatars/<file>` and serves it there, but Vite proxied `/api` and
   **not `/uploads`** → the path hit the SPA fallback → `200 text/html` → the
   `<img>` failed to decode → `Avatar` fell back to initials. The upload
   succeeding is what made it look like a broken upload.
7. **Branding** was the literal string `Project Management` in 5 places + a `PM`
   monogram in 2.

### Traps worth remembering
- **A bare `<form>` inside a flex-column modal breaks the scroll contract.** The
  form needs `min-h-0 flex-1 flex-col` or the body never becomes the scroll
  container and the footer gets clipped by `overflow-hidden`.
- **Calendar dates vs instants.** `startDate`/`dueDate`/`deadline` are calendar
  dates stored as midnight UTC — render them with `timeZone: 'UTC'` or they shift
  a day for anyone west of UTC. `createdAt`/`updatedAt`/`joinedAt` are instants.
- **The task update contract is split.** `PATCH /tasks/:id` does NOT accept
  status/priority/assignee; they have `/status`, `/priority`, `/assignee`. Zod
  strips unknown keys, so a wrong-endpoint call is a **400 "at least one field"**,
  not a 400 naming the field. TypeScript cannot catch it when the body is a
  variable.
- **`/uploads` must be proxied alongside `/api`.** Without it the SPA fallback
  answers `200 text/html` for an image path, so `<img onError>` silently falls
  back and the upload looks broken. `curl` shows `200` either way — check
  `content-type`.
- **Harness: `TableSkeletonRows` renders one placeholder cell per column**, so a
  skeleton row has the right shape and the wrong alignment. Measuring one reports
  "header right, value left" on a correct page. Filter out `.skeleton-shimmer`.
- **Harness: `mobile: true` in `setDeviceMetricsOverride` is non-deterministic**
  here (390 came back as 394 or 437 depending on timing, even after
  `clearDeviceMetricsOverride`). For a layout question use an explicit viewport
  with `mobile: false` — deterministic.
- **Harness: guard `document.body`** in a `waitFor` predicate; mid-navigation it
  is null and `.innerText` throws instead of returning false.
- **Workspace/User serialize `_id` as `id`**; every other model keeps `_id`.
  Cost a seed failure — use `?? .id ?? ._id`.
