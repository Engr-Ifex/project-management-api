## Pre-existing state (inspected first)

- **Critical finding**: `app.js` serves `/uploads` via `express.static` with **no auth**. Fine for public avatars, unusable for private project attachments — so attachments deliberately do NOT live under the static path and are only reachable through an authorized download endpoint.

## Storage architecture (requirement 13)
Provider abstraction so cloud can replace local disk without touching business logic:
- `src/storage/storageProvider.js` — registry + documented contract: `name`, `save({buffer,extension,scope}) -> {key,storedFilename,size}`, `remove(key)`, `exists(key)`, `createReadStream(key)`. `key` is opaque (relative path locally, object key in cloud). **No credentials here** — a cloud provider would read them from env.
- `src/storage/localStorage.provider.js` — local disk under `src/uploads/attachments/<projectId>/<uuid><ext>`.
  - Stored filename is **always generated** (`crypto.randomUUID()` + validated extension); the user's original name never reaches the filesystem.
  - `assertSafeKey` + a second containment re-check in `resolvePath` reject `..`, absolute paths, backslashes and null bytes.
  - Unsafe scope segment falls back to `misc/`.
- Attachment service captures the provider once, so swapping backends is a one-line change.

## 8 routes
`POST|GET …/projects/:projectId/attachments`, `POST|GET …/tasks/:taskId/attachments`, `POST|GET …/tasks/:taskId/comments/:commentId/attachments`, `GET …/attachments/:attachmentId/download`, `DELETE …/attachments/:attachmentId`.
Uploads: `attachment:create`; listings + download: `project:view`; delete: `attachment:delete`. **Multer runs AFTER the permission checks** so unauthorized callers are rejected before any bytes are buffered.

## Security decisions
- Three independent upload checks: allow-listed MIME **and** safe non-blocked extension **and** extension consistent with the MIME. Explicit `BLOCKED_EXTENSIONS` (exe/dll/sh/php/js/html/svg/… ) runs before the consistency check.
- Download sets `Content-Disposition: attachment` (never `inline`), `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`, RFC 5987 UTF-8 filename.
- Cross-project isolation is **query-level**: every lookup is `{_id, project}`, so another project's file is indistinguishable from a missing one → 404 (no existence leak).
- Delete order: DB row first (source of truth), then best-effort file removal — a storage hiccup leaves an invisible orphan rather than a broken record.
- Upload order: file written first; if the DB write then fails the stored object is removed (no orphan).

## Requirement 11 — no uncontrolled references
- Every download re-checks the parent chain: a missing task, a soft-deleted comment, or a vanished stored file → 404.
- Cascade helpers `purgeAttachmentsForComment/Task/Project` delete rows + files. Only the comment path has a caller today (comments are the one entity that gets deleted); task/project helpers are exported for a future hard-delete or retention job since those entities are archived, not deleted.
